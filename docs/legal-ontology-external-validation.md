# 法律本体外部验证流程（分步计划）

外部知识库「法律本体学/法律本体论」的验证流程。核心判断：**"看起来完善"不等于
"已被独立验证"**，因此本流程刻意区分三层，避免把法条文本核验当成建模有效性验证。

## 三层验证，各用什么手段

| 层 | 验什么 | 手段 | 现状 |
| --- | --- | --- | --- |
| L1 法条文本 | 条号是否存在、是否位移、现行文本与引用是否一致 | 北大法宝核验（可脚本化） | 库内已有 26 处条号台账，来源为官方下载件 + 官网交叉；**缺商业法源独立交叉** |
| L2 本体有效性 | 类目语义对错、关系是否成立 | OntoClean / OOPS!（库内 09 夹已有方法论） | 未对现行骨架实际跑过 |
| L3 建模有效性 | 未参与建模者能否用骨架独立走通 | 真实判决书盲测 | 现有 v1–v4 实例报告与真实案件序列均为**建模者自验** |

L1 最容易自动化，也最容易误当成"验证完成"——它只保证引用的法条是真的，
不保证本体建模是对的。L3 才是缺口所在，且它不能靠商业法源代劳。

## 步骤

### 第 1 步：L1 交叉核验（低成本，先拿信号）

1. 在北大法宝控制台获取 Token。
2. 按 [`docs/pkulaw-verification.md`](./pkulaw-verification.md) 阶段 0 挂 MCP connector，
   **零代码**验证连通性与返回结构。
3. 拿条号核销台账的 26 处重跑一遍，与现有结论比对。
   - 全部一致 → 交叉验证成立，L1 可转入常态化。
   - 出现分歧 → 分歧项即为待裁决项，按知识库治理走裁决卡，**不直改骨架**。

验收标准：返回结构须含历史版本与效力期间字段；若不含，说明核验能力不足，
停止后续自动化投入。

### 第 2 步：L3 盲测（真正补缺口）

1. 选一份**未在库中挂接过**的真实判决书（隔离变量：排除已被建模时看过的案子）。
2. 给第三方（未参与建模的人或独立 LLM 实例）判决书 + 骨架，**不给已有挂接答案**。
3. 要求其独立给出：诉请层/抗辩层/要件层/证据层/程序层的挂接结果。
4. 与建模者结果比对，分歧项即为外部验证发现。

参照系：库内 CQ 文档要求「8 条 CQ 各配 3 个真实样例，共 24 个组成验收集」——
这个集合是设计好的，但尚未按此规模实际执行。L3 盲测可复用这套口径。

### 第 3 步：回流（守治理边界）

按争议 009（IMA 骨架为事实源，代码 schema 为投影，禁止反向覆盖）：

- 外部验证发现的问题 → 先落裁决卡（12 夹）→ 裁决生效后才改骨架。
- 形式修正（拼写、数组形态等不改变建模决策的）可直接改并逐条列明。
- 验证报告落 09 夹（该夹已有外部评审跟踪笔记的先例）。
