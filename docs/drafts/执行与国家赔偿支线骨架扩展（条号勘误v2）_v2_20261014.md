## 1. 这条解决什么问题

骨架目前验了民事、刑事、行政——但**执行与国家赔偿的结构与三者都不同**：

- **民事 / 刑事 / 行政都是"审判程序"**——法院居中裁判，解决实体争议；
- **执行是"实现程序"**——法院依生效法律文书强制实现权利，**不解决实体争议，只解决"怎么把判决变成现实"**；
- **国家赔偿是"补救程序"**——国家机关违法行使职权造成损害，国家承担赔偿责任，**不解决原行政 / 刑事行为的合法性，只解决"损失怎么补"**。

这个差异是**程序性质**的差异，不是细节差异：

|维度|民事 / 刑事 / 行政|执行|国家赔偿|
|---|---|---|---|
|程序性质|审判程序（实体争议）|实现程序（判决变现）|补救程序（损失填补）|
|启动依据|起诉 / 自诉 / 公诉|**生效法律文书**（判决 / 裁定 / 调解书 / 仲裁裁决 / 公证债权文书）|**职务行为违法**|
|审查对象|请求权 / 犯罪构成 / 行政行为合法性|**执行依据的效力与执行行为的合法性**|**职务行为的违法性与损害**|
|举证责任|因程序而异|**申请执行人提供财产线索，法院依职权调查**|**赔偿请求人举证损害，赔偿义务机关举证行为合法**|
|裁判方式|判决 / 裁定 / 决定|**执行裁定 / 决定 / 通知**|**赔偿决定 / 判决**|

如果骨架不扩展执行与国家赔偿，执行案件就只能硬套民事的请求权结构——这会把"执行依据的效力"错当成"请求权的成立"，把"执行行为的合法性"错当成"行政行为的合法性"。**这两个错位是执行建模最容易犯的错。**

## 2. 执行程序的建模

新增顶层类 `EnforcementProceeding`（执行程序），与 `Case`（审判程序）并列——执行不是审判的延续，是独立的程序类型。

**类的定义**：

|类|说明|关键属性|
|---|---|---|
|`EnforcementProceeding`|法院依生效法律文书强制实现权利的程序|`enforcementBasis`（执行依据）、`enforcementTarget`（执行财产）、`enforcementMeasure`（执行措施）、`enforcementStatus`（执行状态）|

**关键属性**：

|属性|类型|说明|
|---|---|---|
|`enforcementBasis`|ref|执行依据（`LegalDocument`：生效判决 / 裁定 / 调解书 / 仲裁裁决 / 公证债权文书）|
|`enforcementTarget`|ref|执行财产（`Property`：存款 / 房产 / 车辆 / 股权等）|
|`enforcementMeasure`|enum|执行措施（查封 / 扣押 / 冻结 / 拍卖 / 变卖 / 以物抵债 / 划拨 / 扣留 / 提取）|
|`enforcementStatus`|enum|执行状态（立案 / 财产调查 / 财产控制 / 财产变价 / 分配 / 终结 / 中止 / 终结本次执行程序）|
|`enforcementAmount`|decimal|执行标的金额|
|`satisfiedAmount`|decimal|已执行到位金额|
|`enforcementDate`|date|执行立案日期|

**与民事 `Case` 的关键区别**：民事的 `Case` 是**审判程序**（解决实体争议），执行的 `EnforcementProceeding` 是**实现程序**（把判决变成现实）——`Case` 的输出是判决，`EnforcementProceeding` 的输入是判决。这是执行建模的第一个转向。

## 3. 执行六要件

执行程序的推进依赖六个要件的满足：

|要件|说明|举证责任|note|
|---|---|---|---|
|`hasValidBasis`|执行依据有效|申请执行人|执行依据必须是生效法律文书，未生效或已撤销的不得执行|
|`hasEnforceableContent`|执行依据具有可执行内容|申请执行人|判决必须是给付之诉（给付金钱 / 财物 / 行为），确认之诉与形成之诉原则上不可执行|
|`hasProperty`|被执行人有可供执行的财产|申请执行人提供线索，法院依职权调查|无财产可供执行的，终结本次执行程序（终本）|
|`withinTimeLimit`|在申请执行时效内|申请执行人|申请执行时效为二年（民事诉讼法第 250 条，2023 修正；2021 修正为第 246 条）|
|`jurisdictionCorrect`|执行法院有管辖权|法院依职权审查|由第一审法院或被执行财产所在地法院执行|
|`noLegalObstacle`|无法定执行障碍|法院依职权审查|如被执行人破产、执行标的已灭失等|

**六要件的关系**：**全部满足才可执行，任一不满足即终本或驳回**。这与行政五要件的"全部满足才合法"同构，但内容完全不同——行政审"合法性"，执行审"可执行性"。

**建模落点**：六要件落 L2 的 `Element`，`elementLabel` 分别为"执行依据有效""执行依据具有可执行内容""有可供执行的财产""在申请执行时效内""执行法院有管辖权""无法定执行障碍"。每个要件的 `normBasis` 是民事诉讼法第 235–269 条（执行程序编，2023 修正；核心：管辖第 235 条、时效第 250 条）。

**与民事要件的关键区别**：民事要件是**请求权成立的实体要件**，执行要件是**执行程序推进的程序要件**——前者决定"该不该给"，后者决定"能不能拿到"。这是执行建模的第二个转向。

## 4. 执行救济三链

执行程序的救济是**三链结构**（民事诉讼法第 236–240 条，2023 修正）：

|救济|提起主体|审查对象|审查法院|note|
|---|---|---|---|---|
|执行异议|当事人 / 利害关系人 / 案外人|执行行为的合法性|执行法院|对执行行为不服的，向执行法院提出异议|
|执行复议|当事人 / 利害关系人 / 案外人|执行异议裁定的合法性|上一级法院|对执行异议裁定不服的，向上一级法院申请复议|
|执行监督|当事人 / 利害关系人|执行行为的合法性|上一级法院或最高人民法院|对执行复议裁定不服的，申请执行监督；或检察机关提出检察建议|

**三链的关系**：**异议 → 复议 → 监督**，逐级递进，不可越级。这与审判程序的上诉（一审 → 二审 → 再审）同构，但主体与审查对象不同。

**建模落点**：三链落 L5 的 `Procedure`，`procedureType = 执行救济`，`procedureChain = 异议 / 复议 / 监督`。每个链的 `precondition` 是前一链的完成。

**与审判程序的关键区别**：审判程序的上诉是**对裁判结果不服**，执行救济是**对执行行为不服**——前者是实体争议的延续，后者是程序争议的独立救济。

## 5. 执行 9 类案由的映射路线

法〔2025〕82 号的执行 9 类（强制执行、暂时解除乘坐飞机、高铁限制措施、参与分配、执行担保、确认优先购买权、执行异议、执行复议、执行监督、不予执行仲裁裁决、调解书或公证债权文书），按六要件的共性 + 各类的特殊性建模：

**共性**：9 类都走六要件（执行依据有效、具有可执行内容、有可供执行的财产、在时效内、管辖权正确、无法定障碍），执行救济都走三链（异议 → 复议 → 监督）。

**特殊性**：

|案由|特殊要件|note|
|---|---|---|
|强制执行|六要件全部满足|最基本的执行程序|
|参与分配|多个债权人的分配顺位|分配顺位按法定顺序（优先债权 → 普通债权）|
|执行担保|担保的设立与效力|执行担保与民事担保的衔接|
|确认优先购买权|优先购买权的成立与行使|如承租人的优先购买权|
|执行异议|异议事由的成立|当事人 / 利害关系人 / 案外人的异议事由不同|
|执行复议|复议事由的成立|对异议裁定不服的救济|
|执行监督|监督事由的成立|对复议裁定不服的救济，或检察监督|
|不予执行仲裁裁决、调解书或公证债权文书|不予执行的法定事由|如仲裁程序违法、调解书违反自愿原则等|

**映射路线的优先级**：按收案量与要件清晰度，建议先扩**强制执行**（最高频）、**执行异议**（最高频救济）、**参与分配**（多债权人场景），再扩其余 6 类。

## 6. 国家赔偿的建模

新增顶层类 `StateCompensationClaim`（国家赔偿请求），与 `Claim`（民事主张）、`AdministrativeAct`（行政行为）并列——国家赔偿是独立的请求类型。

**类的定义**：

|类|说明|关键属性|
|---|---|---|
|`StateCompensationClaim`|国家机关违法行使职权造成损害，受害人请求国家赔偿的请求|`compensationType`（赔偿类型）、`dutyAct`（职务行为）、`damage`（损害）、`causation`（因果关系）、`legalScope`（法定赔偿范围）|

**关键属性**：

|属性|类型|说明|
|---|---|---|
|`compensationType`|enum|赔偿类型（行政赔偿 / 刑事赔偿 / 司法赔偿）|
|`dutyAct`|ref|职务行为（`AdministrativeAct` 或 `CriminalProcedure`：如行政处罚、刑事拘留、错误执行等）|
|`damage`|ref|损害（`Damage`：人身损害 / 财产损害 / 精神损害）|
|`causation`|ref|因果关系（`Causation`：职务行为与损害之间的因果关系）|
|`legalScope`|ref|法定赔偿范围（`LegalNorm`：国家赔偿法第 3、4、17、18 条等）|
|`compensationOrgan`|ref|赔偿义务机关（`Party`：作出职务行为的机关或其上级机关）|
|`compensationAmount`|decimal|赔偿金额|

**与民事 `Claim` 的关键区别**：民事的 `Claim` 是**私法上的请求权**（基于合同 / 侵权 / 不当得利等），国家赔偿的 `StateCompensationClaim` 是**公法上的请求权**（基于国家机关的职务行为违法）——前者的义务人是私人，后者的义务人是国家。这是国家赔偿建模的第一个转向。

## 7. 国家赔偿四要件

国家赔偿的成立依赖四个要件（国家赔偿法第 2 条）：

|要件|说明|举证责任|note|
|---|---|---|---|
|`hasDutyAct`|存在职务行为|赔偿请求人|国家机关及其工作人员行使职权的行为|
|`dutyActIllegal`|职务行为违法|赔偿义务机关|职务行为违反法律规定（违法归责原则）|
|`hasDamage`|存在损害|赔偿请求人|人身损害 / 财产损害 / 精神损害|
|`hasCausation`|职务行为与损害之间存在因果关系|赔偿请求人|损害是职务行为造成的|

**四要件的关系**：**全部满足才成立，任一不满足即不成立**。这与民事请求权的"全部满足才成立"同构，但内容完全不同——民事审"请求权的构成要件"，国家赔偿审"职务行为的违法性与损害"。

**举证责任的特殊性**：国家赔偿的举证责任是**混合分配**（国家赔偿法第 26 条）：
- 赔偿请求人举证：职务行为的存在、损害的存在、因果关系；
- 赔偿义务机关举证：职务行为的合法性。

这既不是民事的"谁主张谁举证"，也不是行政的"被告负举证责任"，而是**按要件分配**——这是国家赔偿建模的第二个转向。

## 8. 国家赔偿三类型

国家赔偿按职务行为的性质分为三类型（国家赔偿法第 3、4、17、18 条）：

|类型|职务行为|赔偿义务机关|note|
|---|---|---|---|
|行政赔偿|行政机关及其工作人员违法行使行政职权|作出职务行为的行政机关|如违法拘留、违法罚款、违法征收等|
|刑事赔偿|行使侦查、检察、审判职权的机关及其工作人员违法行使刑事职权|作出职务行为的机关（公安 / 检察 / 法院）|如违法刑事拘留、错误逮捕、错误判决等|
|司法赔偿|法院在民事、行政诉讼中违法采取强制措施、保全措施、执行措施|作出职务行为的法院|如违法保全、错误执行等|

**三类型的程序差异**：

|类型|先行处理|复议|诉讼|
|---|---|---|---|
|行政赔偿|先向赔偿义务机关申请|不服可申请复议|不服复议可提起诉讼|
|刑事赔偿|先向赔偿义务机关申请|不服可申请复议|不服复议可申请赔偿委员会作出决定（**不可诉讼**）|
|司法赔偿|先向赔偿义务机关申请|不服可申请复议|不服复议可申请赔偿委员会作出决定（**不可诉讼**）|

**建模落点**：三类型落 `StateCompensationClaim` 的 `compensationType`，程序链落 L5 的 `Procedure`，`procedureType = 国家赔偿程序`，`procedureChain = 先行处理 → 复议 → 诉讼 / 赔偿委员会决定`。

**关键区别**：行政赔偿可诉讼，刑事赔偿与司法赔偿**不可诉讼**（只能申请赔偿委员会决定）——这是三类型最容易混淆的地方。

## 9. 国家赔偿 4 类案由的映射路线

法〔2025〕82 号的国家赔偿 4 类（违法刑事拘留赔偿、刑事改判无罪赔偿、怠于履行监管职责致伤致死赔偿、错误执行赔偿），按四要件的共性 + 各类的特殊性建模：

**共性**：4 类都走四要件（职务行为、违法、损害、因果关系），举证责任都按要件分配。

**特殊性**：

|案由|职务行为|赔偿类型|note|
|---|---|---|---|
|违法刑事拘留赔偿|刑事拘留|刑事赔偿|拘留超过法定期限或不符合法定条件|
|刑事改判无罪赔偿|错误判决|刑事赔偿|再审改判无罪，原判已执行|
|怠于履行监管职责致伤致死赔偿|监管职责的不作为|行政赔偿|如监狱、看守所怠于履行监管职责|
|错误执行赔偿|执行行为|司法赔偿|执行措施违法或执行标的错误|

**映射路线的优先级**：4 类都是低频，建议按实际需求补充，不设优先级。

## 10. 与民事 / 刑事 / 行政支线的差异总结

|维度|民事|刑事|行政|执行|国家赔偿|
|---|---|---|---|---|---|
|顶层类|`Claim`|`Charge`|`AdministrativeAct`|`EnforcementProceeding`|`StateCompensationClaim`|
|审查对象|请求权成不成立|犯罪构不构成|行政行为合不合法|执行依据可不可执行|职务行为违不违法、损害赔不赔|
|要件结构|请求权构成要件|犯罪构成要件|合法性审查五要件|执行六要件|国家赔偿四要件|
|举证责任|谁主张谁举证（有例外）|公诉机关举证|被告负举证责任|申请执行人提供线索，法院依职权调查|按要件分配（请求人举证职务行为与损害，义务机关举证合法性）|
|裁判方式|支持 / 驳回|有罪 / 无罪|撤销 / 确认违法 / 履行 / 给付 / 变更 / 驳回|执行裁定 / 决定 / 通知|赔偿决定 / 判决|
|程序链|一审 → 二审 → 再审|侦查 → 起诉 → 审判|行政复议 → 行政诉讼|异议 → 复议 → 监督|先行处理 → 复议 → 诉讼 / 赔偿委员会决定|

**一条纪律**：执行与国家赔偿的**审查对象**都不是原审判程序的实体争议——执行审"能不能拿到"，国家赔偿审"损失怎么补"。**不要把执行案件当成审判案件的延续，也不要把国家赔偿当成原行政 / 刑事案件的延续**——它们是独立的程序类型，有独立的要件结构与程序链。

## 11. 拿来能干什么

**第一步·建模执行案件**。拿到一个执行案件，先建 `EnforcementProceeding`（执行程序），再建执行依据（生效法律文书），然后按六要件审查可执行性，最后按三链建模执行救济。

**第二步·建模国家赔偿案件**。拿到一个国家赔偿案件，先建 `StateCompensationClaim`（赔偿请求），再建职务行为（行政 / 刑事 / 司法），然后按四要件审查赔偿请求的成立，最后按三类型确定程序链。

**第三步·复用民事的 I2 格式**。执行与国家赔偿的 I2 映射表按民事的格式填，但 `mapsToElement` 指向的是执行六要件或国家赔偿四要件，不是民事的请求权要件。

**第四步·预置举证责任分配**。执行支线的 `BurdenAssignment` 预置"申请执行人提供财产线索，法院依职权调查"；国家赔偿支线的 `BurdenAssignment` 预置"请求人举证职务行为与损害，义务机关举证合法性"——这是两条支线的默认规则，不需要逐案判断。

**第五步·扩 13 类案由**。按第 5、9 节的优先级，先扩强制执行、执行异议、参与分配三类（执行高频），再扩其余 10 类。

## 12. 缺口与下一步

1. **13 类案由的逐类映射未做**：本件只给了框架与优先级，逐类的 I2 映射表需另行填充；
2. **执行与破产的衔接未细化**：被执行人破产时，执行程序中止，转入破产程序——两条程序链的衔接需在 07 夹程序本体中补充；
3. **国家赔偿的赔偿标准未细化**：国家赔偿法第 33 条规定了侵犯人身自由的日赔偿标准（国家上年度职工日平均工资），但具体数额需按年度更新，本件未建年度更新机制；
4. **执行与国家赔偿的交叉**：错误执行赔偿（司法赔偿）是执行程序与国家赔偿的交叉点，本件只在第 9 节提了一句，未细化衔接规则。
