# 【自撰】归入（Subsumption / 涵摄）建模：事实落到要件的技术路径与常见失败模式

一句话：**归入不是一条关系边，而是一个可争议、可失败、可复审的认定动作；把它建成节点，图谱才能回答"这个事实到底够不够"这个诉讼中最值钱的问题。**

## 1. 这条解决什么问题

一期骨架里，`Fact` 与 `Element` 之间只有 `mapsToElement` 一条边。这条边能表达"这个事实项对应那个要件"，但表达不了三件事：

- **够不够**：事实项已认定，但取值是否满足构成要件（如"借款已交付"成立，但金额未达某门槛）——`mapsToElement` 无值可填。
- **谁主张的归入**：原告主张归入、被告主张不归入、法院最终归入——三方意见不同，一条边装不下。
- **为什么失败**：归入失败有若干种典型模式（要件错配、规范竞合、事实缺口、评价性要件未评价），不做区分就无法做败诉原因归因。

下游图谱最难、也最贵的问题正是**"为什么这个请求没被支持"**。归入节点是唯一能结构化回答它的位置。

## 2. 是什么

归入（Subsumption，德文 Subsumtion，中文亦译"涵摄"）是**把已认定的裁判事实置于法律规范构成要件之下的判断过程**。它的标准形式（司法三段论）：

```
大前提：T（构成要件）→ R（法律效果）
小前提：S（裁判事实）符合 T 的描述
结论：  S 产生 R
```

本体化的关键转变是：**"S 符合 T"这个命题本身是一个可真可假、可争议、需说理的判断**，而不是一条预先存在的边。

归入的四步技术路径（对应可建模的检查点）：

| 步骤 | 动作 | 本体对应 | 失败时的产物 |
|---|---|---|---|
| ① 规范选取 | 找到候选 `Provision` / `Element` | `LegalNorm` → `Element` | 请求权基础错误 |
| ② 要件拆解 | 把 `Element` 拆成可比对的事实项 | `Element` ← `mapsToElement` ← `MaterialFact` | 要件缺失/要件错配 |
| ③ 事实比对 | 把认定值逐项与要件描述比对 | `Subsumption` 节点创建 | 事实缺口 |
| ④ 效果导出 | 归入成功则产生法律效果 | `Subsumption` → `Claim` 的支撑 | 归入失败 |

**归入与"事实认定"的分界**：事实认定回答"发生过什么"（本夹第 1 条的 L2→L3）；归入回答"发生的这个东西算不算数"。前者是**事实问题**，后者是**法律适用问题**。两者在图谱里必须分开——这也是上诉审"事实审/法律审"区分的本体基础。

## 3. 提出者与年份（含中国法制度出处与现行条文）

- **学理来源**：司法三段论与归入的概念源于概念法学（Puchta、Windscheid 等 19 世纪潘德克顿法学），经 Karl Engisch、Arthur Kaufmann 等发展为"归入模式"；对"归入不是纯逻辑推演而是需要评价"的批判，见 Kaufmann《法律获取的程序》（*Das Verfahren der Rechtsgewinnung*）与 Josef Esser 的"个案规范"理论。
- **中国法制度出处**：
  - 《民事诉讼法》（2023 年修正，自 2024 年 1 月 1 日施行）第 7 条"人民法院审理民事案件，必须以事实为根据，以法律为准绳"——归入的立法表述。【已核销：法宝+公开全文双源一致；2021→2023 条号未变】
  - 二审改判规则：《民事诉讼法》（2023 修正）第 177 条——原判决、裁定认定事实错误或者适用法律错误的，以判决、裁定方式依法改判、撤销或者变更——"适用法律错误"即归入层错误的上诉事由。【已核销：法宝+公开全文双源一致；2021→2023 条号未变】
  - 《最高人民法院关于民事诉讼证据的若干规定》（法释〔2019〕19 号，2020 年 5 月 1 日施行）第 85 条："人民法院应当以证据能够证明的案件事实为根据依法作出裁判"——归入必须以已认定事实为基础。
  - 刑事侧：《刑事诉讼法》（2018 年修正）第 55 条第 2 款要求"定罪量刑的事实都有证据证明"——即每一个 `CrimeElement` 都必须有归入结果，不能有空值。
  - 要素式审判：《民事诉讼程序繁简分流改革试点实施办法》（法〔2020〕11 号）第 14 条要求对能概括出固定要素的案件"根据案件要素载明原告、被告意见、证据和法院认定理由、依据及裁判结果"——这是归入过程被强制写进文书的官方模板。

## 4. 核心结构

**`Subsumption` 节点的属性设计**：

| 属性 | 类型 | 说明 |
|---|---|---|
| `subsumedFact` | → `AdjudicativeFact` | 被归入的裁判事实（小前提） |
| `targetElement` | → `Element` / `CrimeElement` | 目标要件（大前提的组成部分） |
| `assertedBy` | → `Party` / `Role` | 谁主张这次归入（一期已有关系名） |
| `contestedBy` | → `Party` | 谁反对 |
| `acceptedBy` | → `Court` | 法院是否采纳（一期已有关系名） |
| `subsumptionOutcome` | 枚举 | `subsumed` / `notSubsumed` / `partiallySubsumed` / `undetermined` |
| `failureMode` | 枚举 | 见下表 |
| `reasoningSpan` | 文本 | 归入说理的原文片段 |
| `establishedInStage` | → `ProcedureStage` | 在哪一审级完成 |
| `concursWith` | → `Subsumption` | 与其他裁判中相同归入的一致/冲突 |

**归入失败的六种典型模式**（`failureMode` 枚举，是本条最有复用价值的部分）：

| 枚举值 | 含义 | 典型场景 | 图谱表现 |
|---|---|---|---|
| `elementMismatch` | 要件错配 | 事实项连到了错误的要件 | `mapsToElement` 边本身是错的 |
| `normSelectionError` | 请求权基础错误 | 选了不该适用的规范 | `LegalNorm` 层错误，要件全对也没用 |
| `factGap` | 事实缺口 | 某个要件无对应已认定事实 | `MaterialFact` 缺失 |
| `valueInsufficient` | 取值不足 | 事实认定了但取值不达标（金额、次数、时长） | `foundValue` 未达要件阈值 |
| `evaluativeNotAssessed` | 评价性要件未评价 | "情节严重""显失公平""合理期限"等需价值补充的要件未作评价 | 要件无 `evaluationNote` |
| `normConcurrence` | 规范竞合 | 同一事实同时落入两个规范，效果冲突 | 两个 `Subsumption` 指向同一 `AdjudicativeFact` |

**评价性要件的特殊处理**：`Element` 设布尔属性 `isEvaluative`。为 `true` 时，`Subsumption` 必须携带 `evaluationNote`（评价理由文本），否则 schema 校验报错。这一条直接对应实践中"法院只说结论不说理由"的可上诉瑕疵。

## 5. 规模与现状活跃度

- **活跃度极高但工程化极低**：归入是所有裁判说理的核心动作，但主流工程实现几乎都把它简化为"要件—事实"二部图的边，没有结果值、没有失败模式。
- **国际侧**：LKIF-Core（2007）用 `constitutes`/`qualifies` 一类关系连接事实与规范条件，但同样不含"归入结果"这一命题层；Carneades（Gordon 等）用可废止论证表达规范适用，能表达归入的攻击与失败，是更接近的参考实现。Bex 等的混合理论（arguments + stories）把"从证据到情节"与"从情节到要件"分开处理，恰好对应本条的"事实认定 / 归入"二分。
- **中国法侧**：要素式审判把归入过程写进了文书模板，是全世界少见的、把归入**显性化**的司法实践，是自建本体的天然优势场景。

## 7. 拿来能干什么（字段级 / 类级建议）

**新增类 `Subsumption`（归入认定节点）**。理由：归入是"事实项 + 要件 + 主张方 + 法院结论 + 失败模式"的五元命题，任何二元关系都无法承载；且它需要独立于 `Fact` 与 `Element` 的生命周期（同一事实对不同要件的归入是不同节点，二审会新建而非修改）。

**新增/复用关系**：
- `subsumedTo`：`AdjudicativeFact` → `Element`（归入的边形式，用于快速遍历；完整信息走 `Subsumption` 节点）
- `supportsClaim`：`Subsumption` → `Claim`（归入成功才连）
- `defeatedBy`：`Subsumption` → `Defense`（被抗辩击破，承接 11 夹 Defense 类）
- `assertedBy` / `acceptedBy`：复用一期已有关系名，**本条扩展其域**为 `Subsumption`（与 11 夹《四要件 vs 三阶层》中出罪事由 `Justification`/`Excuse` 的用法保持一致）
- `elementBelongsToStage`：`Element` → `ReviewStage`（一期已有，刑事侧三阶层）
- `concursWith`：复用

**`Element` 上新增三个属性**（归入的前置配置，落在规范侧而非事实侧）：
- `isEvaluative`：布尔，是否为评价性/不确定性概念
- `thresholdValue`：数值或结构化阈值（金额、期限、次数等），空表示无阈值
- `requiredFactCount`：满足该要件所需的最少已认定事实项数（用于检测 `factGap`）

**给下游图谱的三条落点**：
1. **败诉归因器**：遍历所有 `Subsumption`，筛出 `subsumptionOutcome != subsumed` 的节点，按 `failureMode` 分组统计。这是"为什么输"的唯一结构化答案。
2. **要件覆盖率检查**：`requiredFactCount` 与已连入的 `AdjudicativeFact` 数量比对，差值为负即 `factGap`，可在庭审前预警。
3. **类案比对**：归入层比对（`Subsumption.subsumedFact` + `targetElement` + `failureMode` 三元组相同）比全文相似度精确得多，是类案检索的高价值召回通道。

## 8. 坑与局限

- **坑一：与 `mapsToElement` 混淆。** `mapsToElement` 是**结构映射**（事实项 ↔ 要件，静态，来自要素表）；`subsumedTo` 是**认定结论**（动态，来自法院）。两者必须并存，不可合并。一期 11 夹已明确要素与要件用 `mapsToElement` 连接、映射缺口先留空——本条的 `Subsumption` 正是填补那个"缺口"的机制。
- **坑二：把归入当成纯逻辑。** 归入的核心是**评价**，不是演绎。给 `Subsumption` 加 `probability` 或 `confidence` 数值会误导下游——这个位置应当用 `subsumptionOutcome` 定性 + `evaluationNote` 文本。
- **坑三：刑事三阶层的归入顺序。** 刑事侧归入必须按 `ReviewStage`（构成要件该当性 → 违法性 → 有责性）顺序进行，前一阶层失败则后一阶层不评估。本体里应加 `elementBelongsToStage`（一期已有）并在 `Subsumption` 上冗余 `stageOrder`，避免跨阶层误连。
- **局限**：`failureMode` 六值枚举来自民事审判经验，刑事与行政需另行校验（行政的"适用法律错误"常表现为职权/程序问题，不完全落在要件上）。
- **局限**：规范竞合（`normConcurrence`）的**处理规则**（特别法优于一般法、新法优于旧法、重法优于轻法）属于 05 论证本体的问题，本条只负责把竞合**标注**出来。

## 9. 与其他条目的关系

- **本夹第 1 条（事实分层）**：归入的输入是 `AdjudicativeFact`（L3），不是 `MaterialFact`（L2）。
- **本夹第 5 条（举证责任）**：归入失败的常见原因是举证不能，但两者是不同层——举证责任落在 `Element` 上，归入结果落在 `Subsumption` 上。
- **本夹第 6 条（证明标准）**：证明度不达标导致的归入失败归入 `factGap` 或 `valueInsufficient`。
- **本夹第 10 条（争议焦点）**：`Issue` 常常就是"某个 `Subsumption` 是否被接受"。
- **11 夹《请求权基础树》**：本条在其 `Element` 之上补了"认定结果"层。
- **11 夹《四要件 vs 三阶层》**：刑事侧的 `Subsumption` 需携带 `stage` 字段。
- **05 夹（论证本体）**：归入的**论证结构**（为何符合/不符合）属 05 夹；本条只提供裁判侧的认定结论。
