## 2. 执行清单（按序）

### 第 1 步：选案 + L2 验案号（非建模会话选案，建模侧可代跑 L2）

```powershell
# 把选定案号写入临时 ledger（勿入 git，勿含判决书内容）
# 格式同 scripts/case-ledger.example.json
if ([string]::IsNullOrWhiteSpace($env:YUANDIAN_API_KEY)) {
    $env:YUANDIAN_API_KEY = [Environment]::GetEnvironmentVariable("YUANDIAN_API_KEY", "Machine")
}
node scripts/case-crosscheck.mjs --ledger <临时ledger.json>
# exit 0 = 双源一致；exit 1 = 分歧待核；exit 2 = 未完成核验，均不得当作通过
```

`YUANDIAN_API_KEY` 已配置为系统级环境变量；当前 IDE 进程尚未继承。上面的命令只临时载入当前 shell，不打印或保存密钥；重启 IDE 后新进程可正常继承。

双源连通性已实测：4 个既有案号均查到，`unchecked=0`；3 项 `AGREE`，1 项因法院名称写法不同为 `DISAGREE`，整体 `exit 1`。差异为法宝「广东省佛山市南海市（区）人民法院」与元典「佛山市南海区人民法院」；该项保留待核，不记为全量通过。

### 第 2 步：生成盲测输入包（建模侧）

```powershell
node scripts/make-blindtest-skeleton.mjs
# 产出 blind-test/skeleton-for-blindtest.md（v3.6.2 净版，已过官方校验器 0 error）
```

净版骨架**只含类/关系/枚举/规则/组件定义**，已剥离 §1 修订记录 / §3 验证声明 / §4 迁移说明。

> 已剥离：原第 140-141 行描述了上一轮盲测三方各自把上诉请求塞进 Claim 或 L3/A 翼
> （三条变通路径）——这是最接近"给答案"的一处，已在生成脚本中删除（不是在产物上
> 手工删，否则下次重新生成它会回来）。剥离后官方校验器仍 0 error，AppellateRequest
> 类与"审级请求与 Claim 并列"的语义说明保留。
> 脚本另加 fail-closed 断言：剥离后 YAML 块内若仍残留"盲测"字样即 exit 2，
> 防止源文档改写措辞导致锚点失效而静默产出带答案的净版。
> 仍保留的少量溯源标注（`source: 争议 N`、fix7/fix8）是 schema 出处说明，
> 上一轮 `skeleton-v3.5.1.md` 同样存在，属既有做法。

### 第 3 步：交付盲测方（非建模会话）

给盲测方**且只给**两份文件：
1. 判决书原文（你从法宝/元典取得，存为 `blind-test-judgment.txt`，**不入库**）
2. `blind-test/skeleton-for-blindtest.md`

**不给**：任何已有挂接、攻防图、要素表、"这个案子应该能跑通"之类暗示。

任务书沿用 `docs/drafts/blind-test-package.md` 的产出要求（L1–L6 + 论证翼 + 判项），
但注意该文件第 16 行仍写 `skeleton-v3.5.1.md`——交付时口头/书面改为净版 v3.6.2。

### 第 4 步：比对（建模侧，盲测产出后进行）

```powershell
# 建模者先独立挂接同一案（若该案从未挂接过，建模者挂接即为 modeler 基线）
node scripts/blind-test-diff.mjs `
  --modeler <建模者挂接.md> `
  --rounds <盲测方挂接.md>
# 输出：收敛度 + gap + divergence + extra
```

### 第 5 步：归档（三类）

| 结果 | 处理 |
|---|---|
| 一致 | 结构成立 |
| 分歧但可归因（条号位移/枚举理解差异） | 登记待裁决 |
| **盲测方挂不上（骨架无落点）** | **最有价值**，走 12 夹裁决卡，不直接改骨架 |

### 第 6 步：消耗登记

该案盲测完成后降为 R（回归）池，记入案件池台账；**不得再当盲测证据**。
